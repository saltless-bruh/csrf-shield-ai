## Summary

Implemented the three-tier CSRF token identification strategy described in
PROPOSAL.md §9.3.1 (FR-302). The module is a prerequisite for CSRF rules
001/003/004 and the `token_entropy` ML feature (FR-301).

## Changes Made

| File                               | Action       | Description                                                                                                                  |
| ---------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `src/analysis/token_identifier.py` | **NEW**      | Core module with `TokenMatch`, `shannon_entropy()`, `identify_csrf_token()`, `identify_csrf_header()`, `parse_form_params()` |
| `config/settings.yaml`             | **MODIFIED** | Added `token_identification:` section with configurable `entropy_threshold` (3.5) and `min_token_length` (16)                |
| `tests/test_token_identifier.py`   | **NEW**      | 42 unit tests across 7 test classes                                                                                          |

**Key design decisions:**

- `CSRF_TOKEN_NAMES` stored as `frozenset` (O(1) lookup)
- `TokenMatch.tier` field records which tier matched — useful for downstream rules and logging
- Entropy thresholds passed as keyword args (wired from `settings.yaml` by callers) — no magic numbers in analysis code
- `parse_form_params()` convenience helper avoids re-implementing URL decoding across consumers
